1 · Explicación

¿De dónde sale Linux?

Cuando alguien dice «tengo Linux», casi nunca habla de un solo programa. Habla de un sistema operativo: el software que arranca el ordenador, habla con el hardware y deja que otros programas (navegador, ofimática, juegos) trabajen.

En 1991, un estudiante llamado Linus Torvalds empezó a escribir un núcleo (en inglés, kernel): la pieza que gestiona CPU, memoria y dispositivos. Ese núcleo se llama Linux. Alrededor del núcleo hace falta mucho más: shells, bibliotecas, herramientas de usuario. Gran parte de ese ecosistema proviene del proyecto GNU y de miles de voluntarios y empresas. Por eso a veces se dice GNU/Linux: el núcleo Linux más el entorno libre que lo rodea.

Linux se publica con una licencia que permite estudiar, usar, mejorar y compartir el código (con condiciones). Eso explica por qué hay tantas «variantes» del mismo núcleo: cada equipo elige paquetes, escritorio, ciclo de actualizaciones y soporte. Esas variantes se llaman distribuciones (o distros).

Distribuciones que conviene reconocer

El objetivo 1.1 pide conocer familias y nombres frecuentes (no memorizar mil detalles):

Familia / nombreIdea práctica
DebianBase muy estable; muchas distros «hermanas» parten de aquí.
Ubuntu (y LTS)Basada en Debian; popular en escritorio y servidores. LTS = soporte a largo plazo.
Linux MintEscritorio amable; a menudo basada en Ubuntu/Debian.
Red Hat Enterprise Linux (RHEL)Empresa, soporte comercial, ciclo largo.
CentOS / clonesTradicionalmente cercanos a RHEL en el mundo servidor (el ecosistema ha evolucionado: Rocky, Alma…).
SUSE / openSUSEFuerte en entornos empresariales europeos; openSUSE es la rama comunitaria.
Scientific LinuxHistóricamente orientada a investigación (familia RHEL); hoy suele citarse en contextos de examen/legado.

Truco de estudio: piensa en dos «árboles» grandes — Debian → Ubuntu → Mint y Red Hat → CentOS/clones — más la rama SUSE / openSUSE. Así ordenas los nombres del temario.

Linux embebido: Raspberry Pi, Android y «cosas» que no parecen PC

Linux no vive solo en portátiles. Un sistema embebido es un ordenador metido dentro de otro aparato (router, TV, coche, sensor industrial). Suele tener poca RAM, poco disco y un trabajo concreto.

  • Raspberry Pi: placas baratas para aprender, domótica, laboratorios. El sistema clásico de la comunidad se llamó Raspbian; hoy la imagen oficial se conoce como Raspberry Pi OS (sigue siendo familia Debian).
  • Android: el sistema de la mayoría de móviles. Usa un núcleo Linux, pero la capa de aplicaciones y permisos es distinta a un Ubuntu de escritorio. En el examen, recuerda: Android = Linux en el núcleo, no = «la misma distro de PC».

Linux en la nube

En la nube (servidores alquilados en centros de datos) Linux es el invitado habitual: máquinas virtuales, contenedores y servicios web suelen arrancar imágenes Linux porque son ligeras, automatizables y tienen buen soporte remoto. No necesitas «ver» el monitor: te conectas por red y administras con la línea de órdenes (eso llega en Topics 2–4).

Curiosidad

Un pingüino llamado Tux

La mascota no oficial de Linux es un pingüino. La historia (y el nombre Tux) forma parte de la cultura del proyecto: humor, comunidad y código compartido. No entra en el examen, pero ayuda a recordar que Linux es tanto técnica como comunidad.

2 · Resumen

Qué debes llevarte

  • Linux es sobre todo el núcleo; una distribución empaqueta núcleo + herramientas + política de actualizaciones.
  • Reconoce familias: Debian/Ubuntu/Mint, Red Hat/CentOS, SUSE/openSUSE.
  • Embebido: Raspberry Pi / Raspberry Pi OS (antes Raspbian), y Android (núcleo Linux).
  • Nube: muchas máquinas virtuales y servicios corren Linux sin escritorio local.
  • Ubuntu LTS = versión con soporte extendido (útil en servidores y empresas).

3 · Página de comandos

Comandos para reconocer tu sistema

El objetivo 1.1 es más conceptual que de sintaxis. Aun así, en la terminal puedes comprobar qué estás usando. Practica estos comandos en cualquier Linux (o en una máquina virtual). Explicamos cada uno paso a paso.

uname — nombre del núcleo

Muestra información del sistema referida al núcleo.

$ uname
Linux
Variación: uname -r muestra la versión del núcleo (release).
$ uname -r
6.8.0-40-generic
Variación: uname -a muestra un resumen amplio (todo en una línea).

Paso a paso: 1) Abre un terminal. 2) Escribe uname -a y pulsa Intro. 3) Busca la palabra Linux y un número de versión.

cat /etc/os-release — qué distribución es

Casi todas las distros modernas dejan una ficha legible en /etc/os-release. cat solo imprime el contenido del archivo (no lo modifica). 

$ cat /etc/os-release
NAME="Ubuntu"
VERSION="24.04.1 LTS (Noble Numbat)"
ID=ubuntu
ID_LIKE=debian
...
Variación: grep ^NAME= /etc/os-release filtra solo la línea del nombre (cuando conozcas grep en Topic 3).

Paso a paso: 1) Ejecuta el comando. 2) Mira NAME e ID_LIKE. 3) Si ves ID_LIKE=debian, estás en la familia Debian aunque el nombre comercial sea Ubuntu o Mint.

hostnamectl (si existe) — resumen «humano»

En muchas distros con systemd:

$ hostnamectl
Operating System: Ubuntu 24.04.1 LTS
Kernel: Linux 6.8.0-40-generic
Architecture: x86-64
Si falla: no todas las distros mínimas lo traen. Usa entonces uname + /etc/os-release.

Comandos que aún no necesitas dominar

Más adelante verás lsb_release -a, gestores de paquetes (apt, dnf…) y herramientas de nube. Hoy basta con identificar el sistema.

4 · Ejemplos

Situaciones reales (muchos ejemplos)

Ejemplo 1. Un instituto instala Ubuntu LTS en los portátiles del aula porque quiere actualizaciones predecibles durante varios años.

Ejemplo 2. Un taller de robótica usa Raspberry Pi con Raspberry Pi OS para controlar sensores: barato, documentado y con GPIO.

Ejemplo 3. Un servidor web en la nube arranca una imagen Debian sin escritorio gráfico: menos consumo, acceso por SSH.

Ejemplo 4. El móvil de un compañero es Android: núcleo Linux, pero no «es Ubuntu»; las apps se instalan desde otra tienda y el modelo de permisos es distinto.

Ejemplo 5. Una empresa europea elige SUSE Linux Enterprise por soporte comercial; el equipo de pruebas usa openSUSE en portátiles.

Ejemplo 6. Lees ID_LIKE=debian en un Mint: aunque el logo diga Mint, la base de paquetes «piensa» en Debian/Ubuntu.

Ejemplo 7. Un router doméstico «tiene Linux dentro»: sistema embebido, casi sin interfaz de escritorio, solo página web de administración.

Ejemplo 8. Comparas dos VPS: uno Ubuntu 22.04 LTS y otro Rocky Linux (familia Red Hat). Ambos son Linux; cambian herramientas de paquete y rutas habituales.

5 · Ejercicios

Práctica guiada

  1. Identifica tu sistema. Ejecuta uname -a y cat /etc/os-release. Anota: nombre de distro, si es LTS, y si hay ID_LIKE.
  2. Clasifica tres nombres. Para cada uno di familia aproximada (Debian-like / Red Hat-like / SUSE-like / embebido-móvil): Ubuntu, openSUSE, Android.
  3. Embebido vs escritorio. Escribe dos diferencias entre un PC con Linux Mint y una Raspberry Pi que controla un invernadero.
  4. Nube. Explica en tres frases por qué una empresa puede preferir Linux en la nube aunque los empleados usen Windows en el portátil.
  5. Mapa mental. Dibuja (papel o texto) el árbol Debian → Ubuntu → Mint y sitúa Raspberry Pi OS cerca de Debian.

Ejercicios exploratorios

  1. Busca qué significa LTS y cita un ejemplo de Ubuntu LTS reciente.
  2. Si tienes acceso a dos distros (live USB / VM), compara la salida de /etc/os-release.
  3. Lista tres aparatos de casa que podrían llevar Linux embebido (sin abrirlos: razonamiento).

Pistas (no mires antes de intentar)

Ver pistas
  • Ubuntu LTS suele llevar «LTS» en VERSION de os-release.
  • Android ≠ distro de escritorio; el punto de examen es el núcleo.
  • Embebido: poca interfaz, función fija, a menudo sin teclado local.

Comprueba (estilo preguntas cortas)

Elige la mejor respuesta. Al terminar verás feedback inmediato.

1. ¿Qué es, en sentido estricto, «Linux»?

2. Ubuntu se relaciona habitualmente con…

3. ¿Cuál es un ejemplo de uso embebido?

4. Sobre Android, ¿qué afirmación encaja mejor con el objetivo 1.1?

5. ¿Para qué sirve mirar /etc/os-release?

En la vida real

Elegir distro sin drama

  • Cole o casa: Ubuntu LTS o Mint suelen ser buen primer paso.
  • Proyecto con sensores: Raspberry Pi + imagen oficial.
  • Servidor barato: Debian o Ubuntu Server en VPS.
  • Móvil: Android (Linux en el fondo; otra experiencia de usuario).
Reto práctico · terminal

Ficha de tu sistema en 5 minutos

En un Linux al que tengas acceso, ejecuta:

$ uname -a
$ cat /etc/os-release

Escribe una ficha de 4 líneas: distro, familia (ID_LIKE), ¿LTS?, ¿escritorio / servidor / Pi?
