CSS básico y experiencia de usuario

1º Bachillerato · TIC I · Decreto 40/2022 CyL

Curiosidad

Cuando el estilo se separó del texto

Las primeras webs apenas podían elegir tipo de letra. Las hojas de estilo llegaron para que el mismo documento pudiera presentarse de otra manera sin reescribirlo. Esa separación —contenido y presentación— es la que hoy permite cambiar el aspecto del IES sin tocar el programa del acto.

Objetivos

  1. Escribir reglas CSS con selector y declaraciones.
  2. Enlazar una hoja con ruta relativa o distinguirla de un style de prueba.
  3. Medir el contraste del texto normal con el umbral 4,5:1.
  4. Limitar la medida del renglón y no usar el color como única señal.
  5. Mantener el HTML legible si se desactiva la hoja.

Explicación

CSS es la capa de presentación. HTML dice que un bloque es un título; CSS dice el tamaño, la familia tipográfica, el color y el margen. Separarlas permite cambiar el aspecto del IES Duero sin reescribir el programa de la Semana de la Ciencia. En la práctica de esta lección el HTML y el CSS van en dos cajas y se juntan solo en la vista previa.

Una regla tiene un selector y un bloque de declaraciones. h1 { font-size: 2rem; color: #0E0E0C; } significa: para cada h1, aplica esas propiedades. El punto y coma separa declaraciones. Si falta, la siguiente propiedad se ignora o se interpreta mal. Los comentarios van entre /* y */. No uses //: eso es de otros lenguajes.

Dónde vive la hoja

Tres sitios posibles: un atributo style en la etiqueta (solo para una prueba de un minuto), un <style> en el head (aceptable en una página suelta de clase) y un archivo estilos.css enlazado con <link rel="stylesheet" href="estilos.css"/>. El archivo aparte es el que conviene cuando hay más de una página: el programa y el plano del instituto comparten la misma hoja. La ruta del href es relativa, igual que en la lección 1. La hoja no lleva etiqueta html; es texto de reglas, no un documento.

Caja y herencia

Casi todo elemento es una caja: contenido, relleno (padding), borde y margen (margin). El margen empuja a los vecinos; el relleno es interior y suele heredar el fondo. Confundirlos hace que «el fondo no cubra el hueco». body trae margen del navegador: poner margin: 0 es una decisión consciente, no un ritual. Algunas propiedades se heredan (el color del texto, la familia tipográfica) y otras no (el margen, el borde). Si pintas body { color: #0E0E0C; }, los párrafos heredan ese color salvo que uno lo cambie.

Contraste y experiencia

La experiencia de usuario, en este curso, no es «que quede bonito». Es que se pueda leer, que el título se distinga del párrafo y que el enlace se reconozca. El contraste entre texto y fondo se mide con la relación de luminancias del WCAG. Para texto normal se pide al menos 4,5:1. Para texto grande (en torno a 24 px en regular, o 18 px en negrita) el umbral baja a 3:1. Carbón #0E0E0C sobre crema #FAF7F0 cumple de sobra. Ámbar #C4A15A como color de un párrafo largo sobre crema, no: el ámbar es acento, no tinta de lectura. Gris claro sobre blanco falla aunque «se vea moderno».

El laboratorio calcula esa relación en la propia página. No hace falta una web externa. Si el resultado queda por debajo de 4,5, se cambia el par de colores; no se disculpa con «en mi monitor se ve». Un proyector del salón de actos baja el contraste percibido: por eso el margen de 4,5 no se apura.

Tipografía breve

Una familia con serifa (Georgia, Palatino) funciona en títulos de una página de lectura. Una de palo seco (Segoe UI, sans-serif) funciona en menús y fichas. No hace falta una tercera familia «para que haya diseño». El tamaño de cuerpo no debería bajar de 16 px en pantalla. line-height alrededor de 1,5 evita el bloque compacto. La medida del renglón —cuántos caracteres por línea— se controla con max-width sobre main (unos 38–42 rem, o 65–75 caracteres). Una línea que cruza toda la ventana del proyector se lee mal.

Selectores que bastan esta semana

Elemento (p), clase (.aviso), identificador (#programa) y agrupación (h1, h2). La clase se reutiliza; el identificador, no. No hace falta un selector de cinco niveles (body main section p span): se rompe en cuanto cambias el HTML. La cascada resuelve conflictos por origen, importancia, especificidad y orden. En la práctica gana, casi siempre, la regla más específica y, a igualdad, la que va más abajo en la hoja. Un !important es una alarma, no una herramienta de maquetación.

Pseudoclase útil: a:hover para el estado al pasar el cursor, y :focus para quien navega con teclado. Quitar el contorno de foco (outline: none) sin poner otro indicador deja a esa persona sin saber dónde está. No lo hagas en la entrega.

Comprobación antes de cerrar la lección: el HTML sigue teniendo sentido si quitas la hoja de estilo; el contraste del texto normal cumple 4,5:1; la hoja está enlazada con ruta relativa; no hay colores que signifiquen «error» solo por el rojo, sin una palabra que lo diga.

Glosas de esta lección

Selector. Qué elementos reciben la regla: un nombre de etiqueta, una clase o un id.

Declaración. Pareja propiedad: valor, terminada en punto y coma.

Clase. Atributo class. Se repite. En CSS se escribe con punto: .aviso.

Padding. Relleno interior de la caja. El fondo lo cubre.

Margin. Espacio exterior. No pinta el fondo del elemento.

Herencia. color y font-family pasan a los hijos; el margen, no.

Contraste. Relación de luminancias entre texto y fondo. 4,5:1 para texto normal.

max-width. Tope de anchura. Sirve para que la línea no sea interminable.

:focus. Estado de teclado. No se elimina el contorno sin poner otro.

link rel=stylesheet. Engancha el HTML con la hoja. El href es una ruta relativa.

Ejemplos resueltos

Ejemplo 1 — Punto y coma

  1. Copia la regla h1 tal como está, con las dos propiedades pegadas.
  2. Separa color y font-size con un punto y coma después de cada declaración.
  3. Guarda la hoja y recarga: el tamaño tiene que aplicarse, no descartarse el bloque.
  4. Revisa el resto de reglas con el mismo fallo antes de dar el CSS por cerrado.

Ejemplo 2 — Ámbar de párrafo

  1. Mide el ámbar #C4A15A sobre el fondo #FAF7F0 del párrafo.
  2. Si el par no llega a 4,5:1, no dejes el cuerpo en ámbar aunque «sea la marca».
  3. Vuelve el párrafo a carbón y reserva el ámbar para un borde o una regla.
  4. Vuelve a medir solo el par que queda en el texto.

Ejemplo 3 — Hoja en el escritorio

  1. Abre el HTML y anota la ruta del link a estilos.css.
  2. Comprueba si el archivo está junto al HTML o se quedó en Descargas.
  3. Muévelo al lado del HTML o corrige el href para que coincida con la carpeta real.
  4. Recarga: si el estilo no aparece, la hoja sigue sin encontrarse, no es un fallo del marcado.

Decisiones de aula

Cada caso es una entrega realista del proyecto del IES Duero. Lee la situación antes de mirar la decisión.

1. Tres familias

Situación. Título en una serifa, párrafo en otra y el nav en una tercera «para que haya diseño».

No conviene. Dejarlas porque cada bloque es distinto.

Decisión. Una familia para el texto y, si acaso, la misma en negrita para el nav.

Por qué: Tres familias tipográficas obligan a reaprender el texto en cada bloque, y en una página de acto eso no aporta información. El diseño no consiste en cambiar de letra cada vez que cambia la zona. Basta una familia para el texto y, si hace falta, la misma en negrita para el nav.

2. !important en todo

Situación. Para ganar a una regla anterior se marca todo important.

No conviene. Seguir subiendo especificidad.

Decisión. Borrar la regla vieja o reordenarla. Reservar important para un caso que sepas nombrar.

Por qué: Marcar todo con !important no ordena la cascada: la apaga. Cada regla nueva tendrá que gritar más alto que la anterior y nadie podrá corregir un color sin otra alarma. Se borra o se reordena la regla vieja, y important se reserva para un caso que sepas nombrar.

3. Clase y id intercambiados

Situación. Cada párrafo tiene id distinto y la clase no se usa.

No conviene. Porque así «no se pisan».

Decisión. Una clase .prosa para el aspecto común; id solo si hay un ancla.

Por qué: El id es un nombre propio, único en la página, y sirve para un ancla o un fragmento concreto. La clase es un oficio que se repite: el aspecto de todos los párrafos. Poner un id distinto en cada párrafo y no usar clases impide cambiar el estilo de una sola vez.

4. Color como único aviso

Situación. Las faltas van en rojo y no se dice la palabra «error».

No conviene. Porque el rojo ya se entiende.

Decisión. Escribir la palabra y, si se quiere, reforzar con color.

Por qué: Hay quien no distingue ese rojo, y hay quien imprime en gris. El color puede reforzar, pero la palabra «error» es el aviso que se lee sin depender del matiz. Si el texto no dice qué falla, el color es un código privado del autor.

Errores que se repiten

  • Estilo en cada etiqueta. Veinte style= distintos. Cambiar el cuerpo obliga a tocar veinte sitios. Una regla p en la hoja.
  • Selector eterno. body main section article div p span. Se rompe al quitar un div. Una clase en el párrafo que de verdad quieres.
  • Unidad rara. font-size: 0.5cm en pantalla. px o rem para pantalla. cm, si acaso, al imprimir.
  • Fondo oscuro y texto oscuro. Se copió un tema a medias. Medir el par, no fiarse del recuerdo.
  • Quitar el margen de body y pegar el texto al borde. margin:0 sin padding en el contenido. Si quitas el margen del navegador, pon padding al main.
  • Hoja que no carga y se reescribe el HTML. Se duplican títulos para «forzar» tamaño. Arreglar el href de la hoja.

Comprueba

Abre cada pregunta, responde en el cuaderno y después mira la solución. El párrafo «Por qué» es la parte que se estudia.

1. ¿4,2:1 en un párrafo de 16 px es aceptable si «en mi pantalla se lee»?

Respuesta. No para texto normal. El umbral de referencia es 4,5:1.

Por qué: 4,2:1 se queda por debajo del umbral de referencia para texto normal, que es 4,5:1, aunque en tu pantalla crema se lea bien. El contraste se mide con los dos colores del par, no con la sensación de un monitor concreto. Un párrafo de 16 px no es un rótulo grande: necesita ese mínimo.

2. ¿Qué diferencia hay entre margin y padding si los dos «separan»?

Respuesta. El padding es interior y suele llevar el fondo; el margin es exterior y transparente.

Por qué: Si pintas una ficha y el hueco de dentro queda del color de la página, has usado margin donde querías padding. La caja del modelo no es vocabulario: es el motivo de que el fondo no cubra.

3. ¿Por qué outline: none en los enlaces es un problema aunque quede «más limpio»?

Respuesta. Porque quita la única señal de foco para quien no usa el ratón, salvo que pongas otra.

Por qué: outline: none quita el anillo que señala el enlace cuando se llega con el teclado. Quien no usa el ratón se queda sin saber dónde está el foco, aunque el diseño parezca más limpio. Si lo quitas, tienes que poner otra señal visible, no dejar el foco mudo.
